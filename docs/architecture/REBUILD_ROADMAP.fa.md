# نقشه راه بازسازی AlgoMultiAssetEA (REBUILD_ROADMAP)

## ۱. خلاصه اجرایی

این سند نقشه راه **۱۰ فاز (M0–M9)** برای بازسازی کامل و مبتنی بر شواهد AlgoMultiAssetEA را مستند می‌کند. هدف: تبدیل کدهای موجود به یک سیستم چند-نماد، ایمن، قابل nebاشتن و تولید‌پذیر با مرزهای معامله‌ای صریح، مدیریت حالت هماهنگ و گیت‌های پیش از اجرا قابل ردیابی.

**اصل اولویت:** `درستی > ایمنی > تکرارپذیری > استحکام > قابل‌نباشتن > کارایی > پیچیدگی`

**محدودیت‌های عملیاتی:**
- هیچ راه‌اندازی ترمینال MT5، Strategy Tester، بهینه‌سازی، عملیات بروکر، اجرای اسکریپت MQL5، تغییر پایگاه داده تولیدی یا معاملات زنده در این فاز
- فقط کامپایل MetaEditor مجاز است
- هیچ تغییری در سیاست معامله، محدودیت ریسک، آستانه امتیاز، وزن استراتژی، نگاشت تایم‌فریم، قوانین تلاش مجدد یا معنای مرجعیت بدون تصمیم تایید شده

---

## ۲. معماری هدف و مرزهای مؤلفه‌ها

### ۲.۱ خطوط لوله مفهومی (حفظ شده)
```
MarketData → Features → Regime → Strategies → SignalEngine → TradeFilters 
  → RiskEngine → PortfolioRisk → TradeExecutor → PositionManager
```

### ۲.۲ نقش‌های تایم‌فریم مستقل (تایید شده)
- **Context** (H4/D1): رژیم و بایاس کلان
- **Structure** (H1/H4): ساختار بازار و سطوح کلیدی
- **Setup** (H1/H4): تشخیص الگو و کاندیدا
- **Entry** (M15/M5/M1): تایم‌بندی ورود و مدیریت سفارش

**نکته مهم:** در پیکربندی فعلی `SelectStyleTimeframes()`، `setup_tf == structure_tf` در تمام سه سبک (Scalp/Day/Swing) است. استقلا Setup از Structure **معماری** است اما داده‌های منبع یکسان‌اند. این تضاد مستند شده (D-001 CONFLICT) و نیازمند تصمیم معماری M3 است.

### ۲.۳ مرزهای اجرا
- `TradeExecutor` = **تنها** مرز فراخوانی بروکر
- داشبورد = مشاهده‌گر (هیچ تغییری در تصمیمات معامله)
- زمان‌بندی چند-نماد ≠ تیک نمودار میزبان (پیاده‌سازی از طریق `OnTick` + `OnTimer` + `g_runtime`، کلاس `CScheduler` وجود ندارد)

## ۴. سیاست تکمیل P0–P3

| شدت | تعریف | الزام |
|-------|--------|------|
| **P0** | بلوکر کامپایل/اجرایی، دور زدن گیت ایمنی، آسیب پویا | باید با تصحیح تایید شده بسته شود |
| **P1** | منطق نادرست گیت، نشت حالت، شرایط مسابقه، داده‌های معیوب | باید تصحیح یا پذیرش ریسک صریح با مستندات داشته باشد |
| **P2** | کد مرده، محاسبه تکراری، 不明瞭 مالکیت حالت، پیچیدگی نگهداری | باید در فاز مربوطه بازسازی/حذف شود |
| **P3** | مشاهده‌پذیری، لاگ، متریک،理查س UI، مستندات | باید قبل از تولید حل شود |

**هیچ یافته P0–P3 نمی‌تواند بدون تصحیح تایید شده، پذیرش ریسک صریح و مستند، یا تصمیم معماری/سیاست تایید شده بسته/معلق شود.**
